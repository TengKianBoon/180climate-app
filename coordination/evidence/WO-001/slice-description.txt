# Generated: 2026-06-24

## What the slice does (end-to-end pipe)

1. User opens frontend/index.html (served at GET /)
   - Single HTML page with Leaflet map (CDN)
   - Input form: name, email, IUP name, permit type (HTI/HA), permit years,
     project type (REDD/PEAT), and geometry (coords or GeoJSON paste)

2. POST /api/carbon receives CarbonInput JSON
   - core/geo.py parses geometry → Boundary (area_ha, centroid, within_indonesia)
   - core/forest.py queries deterministic GFW stub → ForestData (annual_loss_ha 2001-2023)
   - engines/carbon/engine.py runs eligibility gates + placeholder estimate range
   - narrative/narrator.py generates template narrative (no LLM — WO-CARBON-005 wires it)
   - Returns EngineResult with verdict, summary, map overlay data, narrative, disclaimer, carrot

3. Frontend renders:
   - Verdict badge (eligible / flagged / not eligible)
   - Placeholder estimate range + disclaimer
   - Leaflet map with centroid marker or polygon boundary
   - Forest loss legend (stub label — real tiles in WO-CARBON-001)
   - Full template narrative
   - Lead capture form

4. POST /api/lead receives lead details
   - api/email.py sends email to info@180climate.net via SMTP (env vars)
   - Falls back to coordination/evidence/email.log when SMTP not configured (CI/dev)
   - Returns {status: "emailed"|"failed", timestamp}
